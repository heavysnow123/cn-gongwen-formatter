# Word 排版工具（Word Formatter Pro 重写版） v1.0.0

开源、干净、可维护的中文文档智能排版工具。对原始 `Word-Formatter-Pro.v2.7.6.exe`
做**静态解析**后，以功能全保留 + 性能/工程优化 + 现代 UI 重做的方式**从零重写**（非反编译再分发，规避原 Pro 许可问题）。

## 功能（与原工具一致，全部保留）

- **主/副标题识别**：文档开头连续居中、字体字号相同的段落；字号不同者判为副标题。
- **一到四级标题**：
  - 一级 `一、`（中文数字 + 顿号）
  - 二级 `（一）`
  - 三级 `1.` / `1、`
  - 四级 `(1)`
- **图/表标题**：居中且以「图/表」开头的段落（居中、小字号）。
- **附件处理**：识别「附件1 / 附件：」并段前分页（可选格式化）。
- **表格格式化**（可选）：表头加粗、统一边框、自动列宽、智能对齐、行高/字号可调。
- **符号标准化**（实验，可选）：中英文标点规范化。
- **TXT / Markdown 导入**：清理 Markdown 标记、空行模式（保留/删单/保留单）、直接生成排版后 docx（强制 A4）。
- **旧格式转换**：`.doc` / `.wps` 经 WPS/Word COM 或 LibreOffice 兜底转为 `.docx`。
- **页面与页码**：页边距、A4、居中的页码（PAGE 域）。
- **大纲级别**：自动设置，生成可导航目录。
- **安全**：绝不修改原文件，全部在临时副本上操作。
- **公文字体检查**：排版前检测系统是否已安装公文必备「仿宋_GB2312 / 楷体_GB2312」等字体，缺失时醒目提示并由用户自行安装（本工具不安装字体、不改系统）。
- **中文字体下拉选择**：所有中文字段（标题/正文/表格/页眉页脚等）均为下拉框，含公文常用字体，也可直接输入自定义字体名。

## 大文件 / 突破上限说明（数百页标书、400MB+）

原 Word-Formatter-Pro 用 python-docx 必须**整文档加载**到内存，文件越大越卡，超大时直接 OOM。
本工具用 `stream.py` 的 **lxml 流式引擎**彻底突破该上限：

- **原理**：用 `etree.iterparse` 边读 `word/document.xml` 边改边写，每处理完一个顶层块
  （`<w:p>` 段落 / `<w:tbl>` 表格）即序列化输出并清除该块，**内存恒定，与文件总大小无关**。
- **实测**：6000+ 段落、含表格与分节符的文档，进程峰值内存仅 **~1.8 MB**（标准整文档模式随段落数线性增长）。
- **标书友好**：
  - 分节符 `<w:sectPr>` **完整保留**（横向附录页、页眉/页脚分节不丢）；
  - 标题/正文/表格/附件分页等格式统一修正照常生效；
  - **页眉/页脚/页码**在两种模式下都支持：标准模式由 python-docx 写入，
    流式模式在 zip 层新建 `headerN.xml`/`footerN.xml` 并改写 `document.xml.rels` 与
    `[Content_Types].xml`、为每个 `<w:sectPr>` 注入引用——只新增小部件、不重排原包，**内存仍恒定**；
  - 页边距（A4/自定义）直接改 `<w:sectPr>` 的 `<w:pgMar>`/`<w:pgSz>`，两种模式一致；
  - 保留原文件其余部件（样式、图片、批注、目录域等）原样拷贝，不破坏包结构。
- **自动降级**：单文件超过 `large_file_threshold_mb`（默认 50MB）**自动走流式模式**，无需手动干预；
  也可在 GUI「其他」页签手动勾选「大文件流式模式」强制开启（用于已知超大文档）。
- **两种模式差异（极小）**：流式模式为每个分节符注入的页眉/页脚引用**指向同一份部件**
  （即所有节共用同一页眉/页脚内容，视觉与逐节独立写入一致）；原文件已自带页眉/页脚的节则**保留原样**、不覆盖。
  其余格式（标题/正文/表格/页码/边距）两种模式完全一致。

> Word 打开大文件卡顿是因为要**渲染/加载内嵌图片**；本工具只解析 XML 文本结构，**不把图片像素读入内存**，
> 因此以图片为主的大文件不会像 Word 那样撑爆内存。GUI 处理在后台线程进行、不冻结，日志区按步长打印进度。
- 单文件超过 `large_file_threshold_mb`（默认 50MB）会弹出大文件预警。
- 超出阈值仍可能较慢属正常（纯 Python 逐段处理），请等待进度提示，不要误判为卡死。
- 仍有上限：文档 XML 本体必须驻留内存（python-docx 机制所限）。若文件为超大单表且内存不足，
  需进一步改用 lxml 流式读写（iterparse）——可单独提出。

## 公文字体检查（仿宋GB / 楷体GB）

公文版式要求正文用仿宋_GB2312、部分标题用楷体_GB2312；系统缺失时 Word 会回退替代字体，导致不达标。
本工具**只检查、不安装**——字体安装属于系统级修改且涉及授权分发，由用户自行完成。

- **检测**：读取 `HKLM/HKCU` 字体注册表，按别名匹配（仿宋/仿宋_GB2312/FangSong 等均视为同一字体）。
- **触发**：「字体」页点「检查字体状态」查看本机情况；开始排版时也会预检并提示缺失。
- **授权字体来源**：仿宋_GB2312 / 楷体_GB2312 为微软专有字体，本工具不内置、不安装；
  请使用您已合法获得的字体并自行安装到系统。思源宋体（大标题）为 SIL OFL 开源，可免费获取安装。
  详见 `fonts/README.txt`。

## 安装与运行

```bash
# 创建虚拟环境（需含 tkinter 的 Python 3.11+）
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt   # 或 pip install python-docx customtkinter pywin32

# 启动 GUI
.venv\Scripts\python.exe -m word_formatter.gui

# 命令行
.venv\Scripts\python.exe -m word_formatter.cli --help
.venv\Scripts\python.exe -m word_formatter.cli -o out *.docx
.venv\Scripts\python.exe -m word_formatter.cli --text "一、标题
正文..." -o result.docx
```

## 构建独立 EXE

```bash
.venv\Scripts\python.exe build.py
# 产物：dist/WordFormatterPro.exe
```
